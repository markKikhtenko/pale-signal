# Модуль маршрутизации OpenClash по чёрным спискам

Module URL:

```text
https://markkikhtenko.github.io/pale-signal/openclash/blacklist-routing.conf
```

Модуль оставляет обычный трафик на `DIRECT`, а заблокированные ресурсы
направляет в существующую группу `PROXY`. Он не добавляет, не заменяет и не
редактирует подписки с прокси. Отключение или удаление модуля возвращает
исходные правила подписки.

Приоритет правил:

1. Существующие специальные правила подписки.
2. Пользовательские домены DIRECT.
3. Пользовательские домены PROXY.
4. Домены Re:filter: сообщества и очищенный список РКН.
5. Пользовательские IP/CIDR DIRECT, включая частные сети.
6. Пользовательские IP/CIDR PROXY.
7. IP-наборы Re:filter: сообщества, Discord и суммарный список.
8. `MATCH,DIRECT`.

Провайдеры Re:filter обновляются каждые 6 часов, пользовательские — каждый час
после редактирования файлов в GitHub. Загрузка выполняется через `DIRECT`, чтобы
избежать цикла запуска прокси. Модуль включает перехват DNS и обработку DNS по
правилам OpenClash, но сохраняет DNS-серверы активного профиля.

## Подключение

1. Используйте актуальный OpenClash с ядром Meta/Mihomo; YAML-блоки модулей
   требуют OpenClash 0.47.081 или новее.
2. Откройте **OpenClash → Overwrite Settings → Overwrite Modules**.
3. Добавьте подписку модуля, вставьте URL выше, обновите и включите её для
   нужного профиля. Если другие модули тоже добавляют правила, применяйте этот
   модуль последним.
4. Примените профиль в режиме `Rule` и выберите рабочий узел в `PROXY`.
5. Один раз проверьте журнал: все провайдеры `pale-signal-*` должны загрузиться.

Для отката отключите модуль и повторно примените профиль.
